<objective>
Prove the cross-OS property with a real Windows runner, and make a presence-only pass impossible.

Purpose: a spec runs in one process on one OS and cannot observe a two-OS property. VER-06 says so in
as many words, which is why the load-bearing control is a job and not a test. The trap is that the
obvious job passes vacuously: the seed key is one per RUN and not per OS, so a presence check on the
Windows leg would go green the moment anyone adds a Windows seed leg, even with cross-OS restore
completely dead. So the verify leg asserts PROVENANCE -- that the body it read was produced on Linux.

Output: a required `producerOs` parameter folded into the payload bytes, the single call restructured
so the two legs' arguments cannot be unified by accident, a two-leg `dogfood-verify` matrix with the
vacuity condition in its comment, and a drift guard that fails if `dogfood-seed` ever grows a matrix.

**VER-06's live clause is NOT closeable in this plan.** `ci.yml:3-7` filters pushes to `main`, and
both dogfood jobs are `if: github.event_name == 'push'`, so neither runs on this branch or on a pull
request. Phase 8's "prove it RED on a fixture AND on a real leg" is half-available here: the fixture
RED is achievable, the live RED is not. This plan closes the code and the workflow text; the live
observation is a `human_needed` item carried to plan 09-07's record and read at the first `main` push
after the merge. Do not write an acceptance check a pre-merge run could satisfy for it.

Vertical slice: one behavioural property (a Windows runner reads a Linux-produced body) closed
end-to-end -- the payload that carries provenance, the two call sites that cannot converge, the job
that samples both OSes, and the guard that keeps the sampling honest.
</objective>
