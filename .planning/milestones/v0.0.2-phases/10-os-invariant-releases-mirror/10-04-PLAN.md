<objective>
Give each `publish` matrix leg a seed key only that leg can produce.

Purpose: OBS-05's first half. Today both legs seed `GITHUB_RUN_ID` and are separated ONLY by
the asset name's OS suffix -- so the moment CORR-02 collapses that suffix, a Windows reader
would derive the exact name the ubuntu leg uploaded and pass unconditionally, even with the
Windows publish path entirely dead. A leg-distinguishable seed is what keeps the names
distinct, and it must exist before the rename.

Output: `lib/mirror-seed.ts` (one pure function), its spec, a third sibling `mirror-seed`
operation branch on the internal dogfood action, and the corrected unknown-operation message.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| action input -> operation dispatch | `operation` selects a verb and a key derivation, never a read-versus-write capability (TRUST-05) |
| derived seed -> the sidecar's SRV-03 route validator | the derived value crosses `HASH_PATTERN` at `server.ts` -> `parseHash`; a non-hex derivation would be rejected there |
| derived seed -> Actions cache key namespace | the seed must be enumerable by `isServerProducedKey` (so it mirrors) while staying disjoint from run ids, Nx task hashes, and the shipped `cafe<run_id>` family |
| bearer token -> the local PUT | reuses `serve()`'s existing per-process CSPRNG secret; no new credential path |
