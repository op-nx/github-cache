<objective>
Run the live proof for O3 and write its evidence, closing the phase.

O3 is proven as an Nx-HASH property, not a storage probe. A storage-level probe for the Linux hash
from a Windows runner would now HIT, and asserting a 404 there would assert a property this milestone
deliberately destroyed. The three parts are: (1) cite CORR-03(b)'s build-gating record that
`H_linux != H_win` for `integration` at the commit; (2) show the Windows `integration` task EXECUTED
carrying no remote-cache label, in a run where the `H_linux` Actions-cache entry demonstrably
existed; (3) a positive control in the same job proving the sidecar and backend were alive.

Purpose: this is the phase's live-CI close, and ROADMAP names it as the whole phase. Nothing here
closes locally.

Output: the O3 section of `11-EVIDENCE.md`, replacing plan 11-03's PENDING placeholder, with the O4
section still RESERVED for Phase 12.

The proving run is a temporary maintainer-authorised push of the phase branch to `main` followed by
an immediate restore, on the contract Phases 9 and 10 both used and recorded. It is chosen over a
`pull_request` run for one decisive reason: only on a push does `github.sha` equal the head, so
`integration`, `hash-parity` and `hash-parity-compare` all measure ONE tree and D-18's citation is
commensurable with the O3 observation. A desirable side effect rather than a regrettable one: the
push re-warms the mirror under the post-Phase-11 hashes, which Phase 12 needs.

This plan performs two outward-facing, hard-to-reverse actions on a PUBLIC repository: a force-push
to the default branch, and a repository-settings write. Both are gated behind one blocking decision
checkpoint, which is why `autonomous` is `false`.
</objective>

## Anti-requirements for O3 specifically

- A storage-level probe for the Linux hash from the Windows runner. It would now HIT, and asserting
  a 404 would assert a property this milestone deliberately destroyed (TEST-09, XOS-03).
- Re-deriving `H_linux != H_win`. CITED from CORR-03(b)'s record at the commit, never re-derived
  (D-18).
- Re-deriving `09-EVIDENCE.md`'s producer-attribution snapshot. Cited, not spent (D-15).
- GATING on the absence of the remote-cache label. It is FALSE on a correct re-run at the same
  commit, and a tripwire that fires on correct work gets disabled (D-17 sub-lock 2).
- Enabling debug logging via a workflow re-run. That path would make the Windows `integration` task
  HIT its own prior entry, which is exactly the condition sub-lock 2 exists to keep out of a gate.
  D-20 uses a fresh push.
- Reading the background sidecar step's `conclusion: cancelled` as a fault. Observed in every run:
  the step is killed by the cancel step while the job conclusion is `success`.
