<objective>
Adopt the measured stderr-immune discriminator, `node --no-warnings -p process.platform`, at every
site in the tree that spells it -- and supersede, rather than silently violate, the written invariant
that says the string must stay byte-identical.

Purpose: DOCS-07 requires the DOCUMENTED command to be stderr-immune "since `hash_runtime` hashes
stdout AND stderr", and D-15 requires the documented command and the repo's own command to be ONE
string. Both halves are now measured rather than assumed. Nx 23.1.0's `hash_runtime.rs:33-35` does
`hash(&[std_out, std_err].concat())` with both streams trimmed, so the requirement's premise is TRUE.
Today's stderr is EMPTY on both CI legs, so the hazard is LATENT -- but a node warning's text carries
the process **PID**, so a warning would not rotate the hash once, it would vary it on EVERY
invocation, producing a permanent 100% MISS that presents to an adopter as a phantom portability
failure. That is what makes the hardening worth its rotation cost.

Output: one changed config value, two exact-equality pins moved with it, five comment/fixture sites
aligned, one rationale block rewritten so no file argues against its own contents, and one
project-level invariant superseded in place.
</objective>
