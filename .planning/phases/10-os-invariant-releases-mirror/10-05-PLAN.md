<objective>
Flip the seed to per-leg and make the read-back prove, offline, that a dead publish leg fails.

Purpose: OBS-05's second half plus XOS-06. The research settled U-01: under `max-parallel: 1`
the leg that runs LAST is the only leg whose dead publish path is detectable, because the
second leg's single enumeration snapshot necessarily post-dates the first leg's seed. Measured
5/5 with 150-190 second margins (run `30401077417`: `publish (ubuntu-24.04-arm)` step ends
`2026-07-28T21:33:39Z`, `publish (windows-11-arm)` seed step starts `21:36:32Z`). OBS-05 names
Windows and Windows measurably runs last, so distinguishable seeds alone WOULD satisfy it --
but only on an ordering GitHub does not document. Asserting the `mirrored-by` label on the
read-back asset replaces that undocumented external guarantee with a documented in-repo one.

Output: the atomic seed flip, the tightened and label-checked read-back, XOS-06's two-way
comment lock, the repo's first `max-parallel` value guard, and the `publish-verify` job
comment's correction.
</objective>
