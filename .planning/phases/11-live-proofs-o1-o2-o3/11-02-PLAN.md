## THE HARD ORDERING RULE FOR THIS PLAN AND THE NEXT

After task 3's `npx nx reset`, **no `nx` invocation of any kind is permitted** until plan 11-03's
measurement run. Not a verification run, not `nx test`, not `nx build`, not `nx show`, not
`nx format:check`. Reasons, both fatal to the proof:

1. Any `nx` invocation repopulates `.nx/workspace-data`, which destroys the cold graph state the
   cold capture just recorded.
2. Any `nx` invocation that runs a cacheable task writes into `.nx/cache`, and a LOCAL cache hit
   short-circuits before the remote is ever queried. TEST-10 states in its own words that a HIT
   recorded without a preceding reset is not accepted, and a `test` entry written by a verification
   run would turn O1's `test` remote hit into a local hit that proves nothing.

`capture-hashes.mjs` is a plain `node` invocation, not an `nx` invocation. It is the one thing that
may run between the reset and the measurement, and task 3 runs it exactly once so that even the
native file cache it populates cannot muddy a second reading.

VALIDATION.md's sampling rate says to run `npm exec nx test github-cache` after every task commit.
That instruction is SUSPENDED for tasks 2 and 3 of this plan and for tasks 1 and 2 of plan 11-03,
for the reason above. It resumes at plan 11-05.
