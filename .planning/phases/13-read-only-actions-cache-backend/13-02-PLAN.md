<objective>
Split `actions-cache-backend.ts` into a read-only BASE factory and a writable factory that COMPOSES
it, so the read-only Actions-cache backend is literally the same implementation as the writable
one's read path (D-01). Widen the `@actions/cache` drift guard from file scope to package scope so
the one evasion the existing scan structurally cannot see is closed.

Purpose: the ROADMAP's named risk for this phase is that two Actions-cache backends means two places
for the cache-version computation to drift — the exact bug Phase 9 existed to fix. The composed
shape makes that drift unrepresentable rather than guarded: there is one `get`, one
`cache.restoreCache` READ call site, and one set of construction guards.

Output: `createReadOnlyActionsCacheBackend()` exported from the existing module, `createActionsCacheBackend()`
rewritten as a spread plus `put`, new behavioural describes, the VER-09 package-scope scan, and a
regenerated committed bundle.
</objective>
