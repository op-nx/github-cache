<objective>
Add the producer-vs-consumer ROLE signal as a strictly-narrowing `CACHE_READ_ONLY` env knob, read by
`selectBackend` as its LAST branch (D-02b, resolved to option (a) by RESEARCH.md Q2).

Purpose: producer-vs-consumer role is not derivable from any GitHub-supplied environment fact — the
three Windows legs run on `push` and same-repo `pull_request`, both of which GitHub keeps fully
read-write, and the 2026-06-26 read-only-cache changelog offers no per-job lever. So a
workflow-author-supplied signal is unavoidable; only its shape was open. Branch ORDER is what makes
"can only narrow" a fact rather than a promise: placed last, the knob's only reachable effect is to
convert the single writable outcome into a read-only one, and it cannot resurrect the Releases
branch, the fail-closed throw, or the memory-degrade branch because control never reaches it from
any of them.

Output: a fifth `selectBackend` outcome, an exhaustive narrowing-only proof, the corrected
outcome-count comment in `memory-backend.ts`, and a regenerated bundle.
</objective>
