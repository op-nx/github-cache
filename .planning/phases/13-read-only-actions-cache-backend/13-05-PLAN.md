<objective>
Convert all three Windows reuse legs to the read-only backend and turn their `[remote cache]` count
records into GATES at `>= 1` per leg (D-04, D-05), correcting every stale rationale in the same
commit (D-06) and pinning the semantic change in a spec (D-07).

Purpose: this is what the phase is FOR. Today the counts are RECORDED and never gated, because with
a writable sidecar the gate is launderable — a broken cross-OS restore makes the leg MISS, execute
and SAVE its own entry, and a re-run of the same commit then HITs that self-produced entry and takes
a `count >= 1` check green with cross-OS reuse dead. Once the legs cannot write, no Windows-produced
entry for those hashes can ever exist, so any HIT is NECESSARILY the ubuntu producer's. That
property is INDUCTIVE, not per-run: it does not depend on job ordering, on re-runs, or on anything
being true of the current run.

Output: three read-only legs, three gates with actionable failure messages, six corrected `ci.yml`
sites, one corrected spec reason string, and six new spec clauses that cannot pass over a leg with
no gate.
</objective>
