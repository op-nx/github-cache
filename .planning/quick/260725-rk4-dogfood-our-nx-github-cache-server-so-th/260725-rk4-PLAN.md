<objective>
Dogfood the shipped @op-nx/github-cache sidecar by routing the repo's OWN cacheable Nx tasks
(build, typecheck, test, integration) through it in `.github/workflows/ci.yml`, so CI produces
real cross-run remote cache hits/misses for the repo's real workloads -- not just the dedicated
seed/read-back proof jobs.

Purpose: Prove the shipped consumer surface (`./start-cache-server` background-step pattern)
works on real Nx tasks end to end, the ultimate self-consistency check for the product.
Output: A modified `ci.yml` where build/typecheck/test/integration each launch the sidecar,
point Nx at it, pass GITHUB_TOKEN, run on both push and PR, and tear the sidecar down with
`cancel:`. The publish-job comment is corrected for the new mirror interaction.
</objective>

  <action>
For each of the `build` (ci.yml:104-113), `typecheck` (115-124), and `test` (126-135) jobs,
insert -- AFTER `- run: npm ci` and BEFORE the existing `- run: npm run <target>` step -- the
consumer-smoke sidecar block, then add `- cancel: cache-server` as the job's final step. Copy
the shape from consumer-smoke (ci.yml:264-324) and the authoritative reusable block in
260725-rk4-RESEARCH.md:72-109. The block is, in order:

1. A regular step named e.g. "Pre-set the Nx cache client vars for the sidecar" with
   `shell: bash` that writes `NX_SELF_HOSTED_REMOTE_CACHE_SERVER=http://127.0.0.1:3000` to
   `$GITHUB_ENV`, generates a hex token with node (per Assumption A3: `node -e` crypto.randomBytes,
   NOT openssl -- keeps ONE block identical to the Windows leg in Task 2), calls `::add-mask::`
   on the token BEFORE writing it, then writes `NX_SELF_HOSTED_REMOTE_CACHE_ACCESS_TOKEN=<token>`
   to `$GITHUB_ENV`.
2. `- uses: ./start-cache-server` with `id: cache-server`, `background: true`,
   `with: port: '3000'`, and `env: GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}`.
3. A `shell: bash` readiness-poll step (30 x 1s, authed GET on `/v1/cache/deadbeef`) that swallows
   curl's exit with `|| true` (NEVER `|| echo 000` -- Pitfall 1, the consumer-smoke "000000" bug).
4. The existing `- run: npm run build` (or typecheck / test).
5. `- cancel: cache-server` (Pitfall 3, MANDATORY -- else the post-job wait hangs on the
   never-exiting serve()).

Locked constraints (CONTEXT.md, corrected by research -- honor exactly):
- Every job passes GITHUB_TOKEN so selectBackend returns the writable backend on push and reads
  default-branch entries on PR (without a token it degrades to the empty memory backend => all-MISS).
- Do NOT add `if: github.event_name == 'push'` to these jobs -- they must run on push AND PR
  (unlike the dogfood/consumer/publish proof jobs).
- Do NOT set the NX_* vars at workflow `env:` level (Pitfall 7 -- that would leak the sidecar url
  into the no-sidecar proof jobs and make every one of their Nx calls try to reach a dead server).
- Use `shell: bash` on the bash steps in ALL four jobs so the SAME block drops verbatim into the
  Windows integration leg in Task 2 (on ubuntu bash is already the default, so this is a harmless
  uniformity choice that avoids maintaining two block variants).

<security_note>

Legitimacy and Environment Availability gates are N/A. The only trust-relevant change is passing
`secrets.GITHUB_TOKEN` to the `./start-cache-server` step on push AND pull_request jobs. This is

before any $GITHUB_ENV write; the loopback bearer token is a distinct, node-minted value) and
reaches the sidecar by process inheritance only, never via the workflow environment file (D-06).

409 path (RESEARCH Finding 3), so no build failure and no cross-scope write. No new attack surface
over the shipped pattern.
