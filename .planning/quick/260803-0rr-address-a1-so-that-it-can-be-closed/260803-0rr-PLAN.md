## The CI + `core.debug()` route is rejected. Three reasons, in order of weight.

### 1. The observation does not need CI, and the local instrument is STRICTLY better

`createReadOnlyMemoryBackend(): ReadableBackend` already exists at
`packages/github-cache/src/backend/memory-backend.ts:63`. Feed it to `createCacheServer`
and every PUT takes the identical `!isWritableBackend(backend)` -> `403` branch at
`server.ts:128-133` that the read-only ACTIONS backend takes. **The backend's identity
cannot matter on this path: `ReadableBackend` has no `put`, and the server answers
before any backend call is made.** That is the D-04 RW/RO seam doing exactly its job.

The harness is not speculative -- **this repo has already run it.**
`10-EVIDENCE-PRE-RENAME.md:55-115` records a local sidecar plus a cold
`NX_CACHE_DIRECTORY` / `NX_WORKSPACE_DATA_DIRECTORY` real `npx nx run`, with a control
table whose sidecar-stderr row literally reads *"no PUT-to-read-only-backend crash"*.
Phase 10 stood on this exact seam and recorded only "no crash"; it never recorded
whether a PUT ARRIVED. That omission is A1's residual, and it is one log line away.

Local is a BETTER instrument here, not a compromise:

| | CI route | Local route |
|---|---|---|
| Discrimination on a null result | **three-way** (no PUT / output lost in teardown / debug not on) | **two-way** -- "output lost" is impossible for a foreground process we started |
| Positive control | must be BUILT (`core.debug` on GET) and is itself unproven mid-life | **free** -- GET lines share the same stdout |
| OS/arch | `windows-11-arm` | Windows 11 arm64 -- same OS and arch family |
| Iterations | one per push + `rerun --debug` | seconds, repeatable |
| Cost | branch, draft PR, perturbation, 2 runs, cleanup | one scratchpad script |

The GET-as-positive-control idea was the right call **for the CI route** -- it is the
only thing that separates "no PUT" from "output died in teardown". Locally that
ambiguity does not exist, so the control comes for free and the instrumentation is
unnecessary. Per-GET noise under debug would have been acceptable (a handful of lines);
the objection is not noise, it is that the line does not need to exist.

### 2. `core.debug()` in `server.ts` is a consumer-contract regression, independent of CI

This one is a genuine soundness objection, and it stands even if you keep the CI route.

`server/server.ts` currently imports only `node:crypto`, `node:http`, `../lib/cache-key.js`
and `../backend/types.js`. It is **GitHub-agnostic**, and it is the module behind the
package's only value export -- `createCacheServer`, the whole of
`EXPECTED_VALUE_EXPORTS` (`public-surface.spec.ts:40`).

Adding `@actions/core` there makes the public barrel transitively depend on a
GitHub-Actions-only package for a consumer who calls `createCacheServer` outside
Actions. `public-server.integration.spec.ts` imports it straight from the barrel. A repo
that maintains VER-09 -- *exactly one non-spec module under `src/` may import
`@actions/cache`* -- has already decided it cares which module imports what; this is the
same class of coupling, at the more exposed module.

Ways out, none of which are needed if the observation is local: put the debug line in
the backend (which already imports `@actions/core`), or inject a logger, or move the tap
to `serve.ts`. All cost more than the observation is worth.

### 3. One inference in the discrimination table is over-strong

Table row 2 reads *"absent refusal -> Nx provably never attempts a store"*. The
observable is narrower: **no PUT reached the sidecar.** A PUT attempted and dropped
before the socket looks identical. This matters because it is the same shape as A1's own
residual -- and the local route inherits the identical limit, so the plan phrases every
conclusion as *"no PUT reached the sidecar"* and never as *"Nx never attempted one"*.
Row 2 still CLOSES A1 (the 403 path is unreachable in practice either way), just on the
narrower, defensible claim.

## Answers to the four questions

- **GET as positive control?** Right for the CI route, and the only thing that would
  have worked there. Moot locally -- the control is free. Per-GET verbosity: fine.
- **Should the refusal line carry the hash?** No objection if it ever ships. Not a
  secret: `ci.yml:1023` already interpolates `own_hash` into a curl URL, the readiness
  poll GETs `/v1/cache/deadbeef` in the clear, and Nx prints `nx-cache-<n>` itself. Moot
  here -- the scratchpad tap logs the full URL and is never committed.
- **Is a docs change required?** **No, and not because it is below threshold -- because
  there is no behaviour change to document.** Nothing ships. `docs-adoption.spec.ts`'s
  `it.each` doc-surface guards, `EXPECTED_ENV_KNOBS` and `EXPECTED_ACTION_INPUTS` are
  untouched by construction. This is a real saving: the CI route would have needed a
  judgement call on all three.
- **Can it avoid CI entirely?** Yes -- see reason 1. That is this plan.
