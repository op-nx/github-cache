<gate_discipline>
Rules every gate below already obeys. Re-read before writing any NEW gate.

- **Exit codes.** `rg`/`git grep` exit 1 on a genuine no-match and 2 when the command
  FAILED. Never read a zero as absence without checking the code. Where a count may be
  zero, the gates use `|| true` and then assert the number explicitly.
- **Dash-leading patterns.** Always `-e`. `git grep '-> foo'` errors with
  `unknown switch`; `git grep -e '-> foo'` does not.
- **Line wraps.** `ci.yml` comments wrap with a `#` continuation, and `rg -U` with `\s+`
  CANNOT bridge a wrap whose continuation carries `#` (use `[\s#]+`). This trap has fired
  three times in this repo. The mitigation used here is structural, not regex-based:
  every gated literal is SHORT and MUST be written on a single comment line. If a literal
  will not fit, shorten the literal, never widen the pattern.

  ("no other job got the clause"). Localization is done separately, by the spec, which
  extracts the `publish` job block before matching.
- **Region gates bound BOTH ends.** The publish-block region is extracted between
  `^  # The per-OS publish matrix` and `^  publish:$` and carries a positive control
  (`BOUNDED FAILURE MODE:`, pre-existing) proving the extraction worked.
- **Positive greps only, on prose.** This plan uses NO negative grep against comment text,

- **Deletion test.** Every gate below fails if the guarded text is deleted, fails if
