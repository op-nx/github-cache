# Quick Task 260809-2s6: stop the publish mirror from re-enumerating prior runs' seed entries - Context

**Gathered:** 2026-08-09
**Status:** Ready for planning

<domain>
## Task Boundary

The `publish` mirror enumerates and attempts to restore CI's own single-use seed entries as
if they were cache content. Measured on run `31281406708`:

- `readMisses` 63 of `scanned` 149, of which only **15 are real Nx task hashes** (the
  pre-`47597a6` rotation cohort). The other **48 are seeds**.
- **All 22** post-rotation misses are seeds; zero are real task hashes.
- **78 of the 85 successful restores** were already present in the shard -- the bytes were
  fetched and discarded.
- **38 of the 87** assets in `nx-cache-202608` are seeds, not cache content.

The miss set is SELF-PERPETUATING: an entry that misses on restore can never be mirrored, so
it is never in the shard, so it is retried on every future run and can never succeed.
Measured: zero of the 63 misses were present in the shard, which is structural rather than
coincidental.

IN SCOPE: stop the ongoing accrual, and make the OBS-01 counts interpretable.
OUT OF SCOPE: deleting the 38 existing shard assets; diagnosing the 15 real pre-rotation
hashes; any merge.

</domain>

<decisions>
## Implementation Decisions

### D1 -- Filter seeds by STRUCTURAL disjointness, not by key shape heuristics

Skip `cafe<run_id>` and `feed<index><run_id>` entries whose embedded run id is not the
current run.

This is safe by construction, not by guesswork. `lib/mirror-seed.ts` establishes it
deliberately: "The hex LETTERS are what make disjointness STRUCTURAL rather than
probabilistic: both competing key spaces -- workflow run ids and Nx task hashes -- are
all-decimal." A real Nx hash therefore cannot be misclassified as a seed.

REJECTED ALTERNATIVE -- a shape heuristic on digit length. Its failure direction is the
dangerous one: a real hash misread as a seed silently stops being mirrored, violating
XOS-07 / CORR-02 with nothing going red.

### D2 -- Give the `dogfood-seed` bare-run-id seed its own hex marker word

The third seed family is keyed by the bare `${{ github.run_id }}`, which is all-decimal and
therefore NOT structurally separable from an Nx task hash. It is the only genuinely ambiguous
family, and it accounts for 28 of the 48 stale seeds.

`mirror-seed.ts` records that the bare run id is the SUPERSEDED design -- `publish-verify`
already moved off it to per-leg `feed<i>` keys. This finishes that migration for the
remaining family, following the convention the docblock states explicitly: a DIFFERENT
marker word per family "is the point, not a coincidence".

This is NOT a new prefix and NOT a namespace switch. Keys stay under `nx-cache-`. It is the
third instance of an in-repo pattern already used twice (`cafe`, `feed<i>`).

ACCEPTED COST: entries already written under the bare-run-id shape stay unfilterable until
they evict. Explicitly fine -- see C4.

### D3 -- Test shard membership BEFORE attempting the restore

The loop currently restores every enumerated hash and only then discards it via D-05
first-write-wins. Reordering skips already-present names without a round-trip.

Measured effect on run `31281406708`: 78 of 149 restores per leg eliminated (~52%). The
shard names are already materialized into a `Set`, so the check is O(1). Semantics are
unchanged -- an already-present name is never re-uploaded either way.

This does NOT reduce `readMisses` (zero of the 63 were in the shard). It is a cost fix, kept
separate from D1/D2 in the reporting so neither is credited with the other's effect.

### D4 -- Split the OBS-01 metric so one number stops meaning two things

`restore-MISS (of skipped)` currently conflates unrestorable entries with already-present
skips. That conflation is the direct reason a 42% miss rate went unread for 11 days across
two windows.

Report unrestorable-misses separately from already-present skips.

### D5 -- Add a guard for the PARTIAL case

The existing all-restore-MISS warning fires only on the total case
(`readMisses == hashes.length && mirrored == 0`), which is why it stayed correctly silent
while 42% missed. A partial/steady-state signal is what closes this defect class.

Its threshold must not be a bare default. It is asserted against a MEASURED baseline: after
D1+D2 the expected steady state is the real-hash cohort only.

### Claude's Discretion

- Exact structure of the split metric rows, provided `scanned` still reconciles.
- The marker word chosen in D2, provided it is hex-letter-leading and distinct from both
  `cafe` and `feed`.
- Where the D5 threshold lives and its exact form.

</decisions>

<constraints>
## Locked Constraints -- do not revisit

### C1 -- `publish-verify` REQUIRES the current run's seed to be mirrored

`assertPublishedByThisLeg` reads `asset.label` from the RELEASE SHARD, not the Actions cache.
The round-trip is seed -> publish mirrors it -> read back and check `mirrored-by`. Its own
error text calls a missing asset "a DEAD publish path".

Excluding seeds wholesale turns BOTH `publish-verify` legs red. Only PRIOR runs' seeds may be
skipped.

### C2 -- `actions: write` MUST NOT be requested. Non-negotiable.

Its absence IS the registered mitigation for **T-11-01 (elevation of privilege, HIGH)`**,
asserted workspace-wide against a passing positive control and pinned by spec cases in
`dogfood-cross-os.spec.ts` and `docs-same-os-claims.spec.ts`. `ci.yml` names it as "the cache
DELETE verb".

This DISQUALIFIES the self-cleanup design (having the round-trip delete its own cache entry),
which was considered and rejected on this ground alone.

### C3 -- Do NOT touch the `listCacheEntries` ref scoping

The `ref` argument is the sole in-repo control for TRUST-10 / C1 / C2 / C16: only
default-branch entries are enumerated, so only they can reach a world-readable Release. Losing
it is an information-disclosure change that fails silently -- nothing goes red.

### C4 -- No retroactive correctness requirement

Maintainer decision: existing stale entries may rot. The fix must stop the ACCRUAL; it does
not need to repair the 48 already in place.

### C5 -- No new key PREFIX and no namespace switch

Maintainer decision: this repo has already burned one namespace (the legacy `<hash>-<os>`
asset names Phase 10 replaced). Keys stay under `nx-cache-`. D2 is a marker word within the
existing namespace, which is the established convention -- not a switch.

### C6 -- Nothing may be merged, and no shard assets deleted

The milestone is frozen pending the maintainer's additional code and security reviews. This
task lands BEFORE those reviews by explicit decision, so its diff is in their scope.

### C7 -- Execute on the MAIN tree, NOT in a worktree

Two measured reasons. A junctioned `node_modules` makes esbuild rewrite module paths with no
source edit, so `check:action` returns a FALSE drift verdict inside a worktree. And the action
bundle inlines `serve()`-reachable sources, so `start-cache-server/index.js` must be
regenerated in the SAME commit as any reachable source edit or `action-bundle-drift` fails
that commit.

</constraints>
