# Plan 02: Wilson lower bound on the partial-miss branch

## Why this exists

Plan 01's D5 shipped a bare ratio at one half. Its own comment justified the constant with a
DERIVED figure (33%) that a code review then showed was wrong. A live measurement now exists,
so the constant's justification can be replaced with a measurement and the rule can be made
scale-invariant for public consumers.

## MEASURED -- run `31305961054`, head `e3bf98b`, both publish legs

| leg | scanned | mirrored | readMisses | alreadyPresent | ratio | Wilson LB |
|---|---|---|---|---|---|---|
| ubuntu-24.04-arm | 112 | 10 | 43 | 59 | 0.384 | 0.299 |
| windows-11-arm | 113 | 1 | 43 | 69 | 0.381 | 0.296 |

Both estimates that preceded this were wrong in opposite directions: the shipped comment said
33% (43/129), a review correction said 41% (43/106). The truth is 38.4% (43/112). The miss
COUNT of 43 was right in both; the DENOMINATOR was wrong in both. That is the reason every
figure in the rewritten comment must be labelled MEASURED with its run id.

## Decisions locked here (auto-decided; gray areas rated before locking)

None of these sat in the high-impact/low-confidence quadrant, which is why they were locked
without a checkpoint rather than as a convenience.

**W-D1 -- the denominator stays `hashes.length`.** MEASURED, not argued: thresholding on
attempted-only (`scanned - alreadyPresent`) gives 43/53 = 0.811 on ubuntu and 43/44 = 0.977 on
windows, so it would fire on BOTH legs on a healthy run. The cause is structural and permanent:
ubuntu publishes first, so the second leg of any matrix finds nearly everything already present
and its attempted-miss rate is dominated by leg ordering, not by cache health. The
"incoherent" mixed denominator is the one that is stable across leg order.

**W-D2 -- the target rate stays 0.5.** The maintainer has ruled that tuning to this repo's
numbers is acceptable while it is the only consumer, PROVIDED the change moves toward a generic
solution. Wilson is what supplies that: the rule becomes scale-invariant, so at stable release
only one number needs revisiting rather than the whole rule.

**W-D3 -- z = 1.96.** Standard two-sided 95% constant. It is not tuned to anything in this
repo, which is the property that matters.

**W-D4 -- describe it as a REGULARISER, never a confidence bound.** A restore MISS is
deterministic given (entry cohort, leg platform) -- the cache version either matches or it does
not -- so there is no superpopulation and an interval has no estimand. The formula still does
the useful thing (it penalises small samples), but calling it a confidence bound in a comment
would ship a false justification, which is the exact defect class plan 01's review removed five
instances of.

**W-D5 -- no minimum-N floor.** IN-03 is closed by construction rather than by a constant: the
bound cannot reach 0.5 below n=4, and at n=4 only a 4/4 miss clears it, which the total-case
branch already owns.
