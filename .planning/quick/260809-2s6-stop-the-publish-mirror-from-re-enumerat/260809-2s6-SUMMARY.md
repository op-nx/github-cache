# Quick Task 260809-2s6: Stop the publish mirror from re-enumerating prior runs' seeds -- Summary

Structural seed filter plus a split OBS-01 metric: the publish mirror no longer
restores prior runs' single-use CI seeds, no longer round-trips entries already in
the shard, and no longer reports two different things under one number.

## What Was Built

**Task 1 -- the third marker word (D2).** Commit `46f0b8a`.

`dogfood-seed` and `dogfood-verify` moved from `hash: ${{ github.run_id }}` to
`hash: bead${{ github.run_id }}`. The bare run id is all-decimal, which is exactly
the character class of a real Nx task hash, so this family was the only genuinely
unfilterable one -- and 28 of the 48 stale seed entries belong to it. The marker
word is hex letters, so the key stays inside the server's `^[a-f0-9]{1,512}$`
validator while becoming structurally separable.

The prose that asserted the superseded shape was swept across six sites plus two
in a spec. One of them was not in RESEARCH's list and was found by reading the
job: dogfood-seed's own two-line rationale justified the choice on the ground that
the run id is ALREADY all-decimal and needs no massaging -- a sentence this edit
makes false.

A new spec case pins each job's `hash:` value WHOLE and anchored plus their
equality. Proven non-vacuous by mutation: reverting only `dogfood-verify` reddens
it with a message naming the round-trip.

**Task 2 -- the filter and the reorder (D1, D3).** Commit `3cdf87c`.

`isOtherRunsSeed` answers "is this a seed belonging to some OTHER run" -- true when
the hash begins with one of the three marker words AND does not end with the
current run id. Wired as a second `.filter` in the existing pipeline, after the
`parseHash` narrowing and before the `Set`, so a filtered seed cannot inflate the
distinct-hash count. `runPublish` reads `process.env.GITHUB_RUN_ID` and forwards it
as `PublishOptions.runId`.

Shard membership now runs at the top of the loop, above the restore, guarded on the
lazily-resolved shard being defined.

**Task 3 -- the split metric and the partial guard (D4, D5).** Commit `e78a842`.

`PublishResult.alreadyPresent`, a second strict subset of `skipped`, incremented
from both membership branches and NOT from the duplicate-upload race. A summary row
added; the existing miss row's label untouched. All eleven whole-result assertions
updated with case-correct values.

`PARTIAL_READ_MISS_WARN_RATIO = 0.5` and a second warning branch written as an
`else if` on the existing total-case branch.

## What changed

**W1 -- the rule.** A module-local `wilsonLowerBound(successes, trials)` with
`WILSON_Z = 1.96` as a named local constant; the branch's second clause is now
`wilsonLowerBound(readMisses, hashes.length) >= PARTIAL_READ_MISS_WARN_RATIO`,
with `readMisses > 0` kept as the first clause. The helper is NOT exported -- the
specs drive it through `publishMirror`, so they prove the branch reads it rather
than pinning arithmetic in isolation. IN-03 closes by construction: no minimum-N
floor exists or is needed, because the bound cannot reach one half below four
trials and at four only a 4/4 miss clears it, which the total-case gate owns.

The helper's docblock calls it a SMALL-SAMPLE REGULARISER and explicitly refuses
the confidence-bound framing (W-D4): a restore MISS is deterministic given (entry
cohort, leg platform), so there is no superpopulation and no estimand.

**W2 -- the figures.** Every derived figure is gone from both files. The branch
now records the measurement from run `31305961054` at head `e3bf98b` -- 43 of 112
on ubuntu-24.04-arm (38.4%), 43 of 113 on windows-11-arm (38.1%), bound 0.299,
silent -- and records why the denominator stays `hashes.length`: attempted-only
measures 43/53 = 0.811 and 43/44 = 0.977 on the same run and would fire on both
legs of a healthy run, because `max-parallel: 1` makes the second leg's
attempted-miss rate a function of leg order.

Deleted: the 33%/41% derivation, the intermediate-band paragraph (its premise WAS
the estimate), and the "one half survives being wrong about the estimate"
argument. The revisit-trigger paragraph is rewritten rather than deleted -- its
trigger has fired, and the run that fired it is now the one quoted.

All five falsified spec-prose items were swept in the same commit as the source
rewrite: the 4-entry claim (now 10-entry), the pointer to the deleted
intermediate band, the revisit trigger, the "threshold is ONE HALF" title (now a
target rate a bound must reach), and the "derived post-fix baseline" message.

**W3 -- the warning.** The closing sentence that instructed a reader to compare
against this repository's own later reading is gone. What ships names only the
count, the enumeration size, which denominator the proportion is over, and the
sibling gate's two candidate causes. A spec pins the call count and asserts over
the FLATTENED calls -- never `not.toHaveBeenCalledWith`, which negates the
predicate rather than the quantifier -- with the three forbidden phrases split by
a single-character class.
